# 期货市场运作机制样板标准

## 1. 本次处理的 PDF

- PDF 名称：`02期货市场的运作机制.pdf`
- 样板目录：`data/generated/derivatives/sample/`
- 资料记录路径：`source-materials/derivatives/02期货市场的运作机制.pdf`
- 当前状态：本目录下的 sample 结果视为“合格样板版本”。

本样板只处理这一份章节 PDF，不代表批量处理结果，也不应直接覆盖正式导入目录。

## 2. 当前框架结构

当前 framework 的 chapter 结构采用以下层级：

1. 章节总览
2. 核心机制
3. 核心概念
4. 关键公式与计算逻辑
5. 易混点
6. 复习路径

结构原则：

- 本章定位、课程作用和主线放在 chapter summary 与“章节总览”中。
- 具体知识点放在 nodes 知识树中。
- 表格、流程、公式和概念关系交给 visualBlocks 展示。
- 页面可见内容面向学生复习，不展示内部来源、页码、chunk 或整理痕迹。

## 3. concise 和 detailed 的区别

`framework-concise.json` 用于考前快速复习：

- 内容更短。
- 节点更少。
- 只保留主线、核心概念、关键机制、核心计算逻辑和最重要的 visualBlocks。
- 适合学生在复习后期快速抓重点。

`framework-detailed.json` 用于系统学习：

- 内容更完整。
- 展开机制、概念关系、公式逻辑、制度扩展、易混点和复习路径。
- visualBlocks 更多，覆盖流程、对比表、公式卡和概念图。
- 适合学生第一次系统梳理章节。

## 4. visualBlocks 使用方式

当前样板使用以下 visualBlocks 类型：

- `process_flow`：表达机制流程，例如期货交易基本流程、每日盯市、追加保证金、平仓或交割、中央清算。
- `comparison_table`：表达概念对比，例如远期合约 vs 期货合约、初始保证金 vs 维持保证金、平仓 vs 交割、场外抵押 vs 中央清算。
- `formula_card`：表达计算逻辑，例如期货每日盈亏计算，并说明变量、使用场景、多头/空头方向和常见错误。
- `concept_map`：表达核心概念关系，例如期货合约、保证金、每日结算、结算中心、平仓和交割之间的关系。

使用原则：

- 能重建为可视化内容的表格、流程、公式和关系，不写成纯文字长段。
- 不使用 `image` block，除非已有真实可引用图片并放入 `public/`。
- visualBlocks 不保留 `source` 字段，避免未来页面展示来源信息。

## 5. 已解决的问题

当前样板已经解决以下展示问题：

- 不显示来源：页面可见内容不包含资料来源、页码、chunk、source 等内部信息。
- 不出现空引用：页面可见内容不再出现“表2.1”“图2.1”等指向原始 PDF 图表但网页未展示的引用。
- 本章定位与知识点分层：章节定位放在 summary 和章节总览中，具体知识点放入知识树。
- 表格、流程、公式用 visualBlocks 表达：对比关系、机制流程、计算逻辑和概念关系均用当前 schema 支持的可视化块承载。

## 6. 后续处理其他 PDF 必须遵守的规则

后续每处理一个章节 PDF，必须遵守：

1. 一次只处理一个 PDF，不批量混合多个章节。
2. 不调用在线 AI API，不生成题库，不导入数据库。
3. 不修改学生端页面、不修改 Prisma schema、不修改 `fixed-course-framework.ts`。
4. 生成内容只写入约定的 sample 或对应离线生成目录，不把真实 PDF 提交到 Git。
5. framework JSON 必须通过 `framework-schema.ts` 校验。
6. 页面可见文字不得出现来源、页码、chunk、source、内部整理说明。
7. 页面可见文字不得出现未实际展示的表格或图示引用。
8. 章节定位必须与具体知识点分层，不能把“本章定位”和具体知识点平铺成同级重点。
9. 对比关系优先使用 `comparison_table`。
10. 机制链条优先使用 `process_flow`。
11. 公式和计算逻辑优先使用 `formula_card`。
12. 多概念关系优先使用 `concept_map`。
13. concise 和 detailed 必须明显区分，不允许只是同一内容长短略改。

## 7. 仍需要人工审核的地方

即使样板已经合格，后续处理仍需要人工审核：

- PDF 文本抽取是否乱码，表格或扫描页是否有误读。
- 保证金、盈亏、现金流方向等计算逻辑是否符合老师授课口径。
- visualBlocks 是否真的比纯文字更清楚。
- concise 是否足够短，detailed 是否足够完整。
- 页面上是否仍有来源信息、空引用或内部处理痕迹。
- 章节主线是否符合本门课的复习重点。
- 是否适合进入正式导入流程。
