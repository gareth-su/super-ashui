# 内容生成标准

本文件是 study-ai-mvp 后续所有课程内容生成与章节增强任务的全局标准。处理任何新课程、sample、full 或单章增强前，内容生成模型必须先阅读并遵守本文件；如果用户没有特别说明，应优先遵守本文件。

## 1. 项目内容定位

study-ai-mvp 的课程内容主要服务期末复习，同时兼顾日常学习。

生成目标不是单纯完整搬运 PPT，也不是只做课程提纲，而是：

- 完整吸收原始资料；
- 按期末复习价值分层展示；
- 把核心公式、核心机制、典型计算题、关键判断逻辑放在主学习路径；
- 把新闻链接、市场截图、机构实践、延伸阅读放在辅助或拓展位置；
- 用 visualBlocks 重建资料中的公式、表格、流程、案例、例题、现金流图、收益图和判断路径。

内容生成时必须避免两个极端：

- 不能把 50 页 PPT 压成几条提纲；
- 也不能把 PPT 中所有内容等权展示。

## 2. P0/P1/P2/P3 分层标准

每章增强前必须先做复习价值分层，再写入 framework JSON。

### P0：必须掌握

学生如果不会，可能直接影响期末考试答题。

包括：

- 核心定义；
- 核心公式；
- 核心机制；
- 典型计算题；
- 关键判断逻辑；
- 老师知识目标、掌握要求、回顾页反复强调的内容；
- 能直接转化为选择题、判断题、计算题、简答题的内容。

展示要求：

- 必须进入主学习模块；
- 公式、例题、图表要靠近对应知识点；
- 不要折叠或弱化；
- 优先生成 formula_card、example_box、process_flow、data_table、comparison_table 等结构化内容。

### P1：重点理解

服务 P0 的重要解释和机制。

包括：

- 核心公式背后的机制解释；
- 重要对比；
- 重要图示；
- 常见变形；
- 关键影响因素；
- 与 P0 紧密相关的制度逻辑、市场逻辑或风险逻辑。

展示要求：

- 进入主学习模块；
- 放在 P0 内容之后或与 P0 自然结合；
- 可以用 comparison_table、chart_explanation、process_flow、curve_chart、case_card 等表达。

### P2：辅助复习

有助于理解课程，但考试价值低于 P0/P1。

包括：

- 背景说明；
- 制度细节；
- 市场分类；
- 课堂补充；
- 与核心考点相关但不是主线的材料；
- 低频应用场景。

展示要求：

- 放在对应模块后部；
- 如果前端支持折叠，作为补充理解；
- 不要占用主视觉；
- 不要生成大量醒目的 visualBlocks。

### P3：拓展材料

与课程相关，但主要用于拓展、市场观察或课外阅读。

包括：

- 新闻链接；
- 研究报告链接；
- 机构实践截图；
- 数据库介绍；
- 市场延伸阅读；
- PPT 目录中出现但正文没有系统展开的内容。

展示要求：

- 放入拓展材料或对应模块末尾；
- 不进入主学习路径；
- 不为 P3 内容硬造复杂 visualBlocks；
- 不把截图、链接和核心公式例题等权展示。

## 3. 例题 / 应用题 / 推导链识别规则

如果 PPT 中出现以下信号，必须优先判断是否应生成 example_box：

- 例；
- 应用；
- 问；
- 答；
- 思考；
- 求解得；
- 根据下表；
- 如何通过；
- 公允价值；
- 按照一价原则；
- 计算；
- 判断。

如果连续多页出现以下结构，也必须合并为一个完整 example_box：

题目 → 表格/条件 → 设变量/列方程 → 解答/结论。

必须特别注意：

- 完整应用题不能只处理成 data_table；
- 连续页推导不能只抽其中一页的表格；
- 公式卡不能替代例题步骤；
- chart_explanation 不能替代计算题解法；
- 如果表格服务于题目，它是 example_box 的已知条件，而不是例题本身。

formula_card 与 example_box 的边界必须明确：

- 如果内容包含已知条件、问题 / 求解目标、代入过程、多步计算、数值求解、结果解释、课堂例题语境，就不应只做 formula_card。
- 如果内容是在“用市场价格校准某个未知量”“根据条件求某个节点值”“给定条件求价格 / 节点 / 收益 / 价值 / 参数”“根据课堂示例推导某个结果”，应优先建模为 example_box、case_card 或学习模块中的“校准例题 / 计算例题”。
- formula_card 适合定义性公式、稳定关系式、单独需要记忆的计算关系，以及变量说明清晰但不承担完整求解过程的公式。
- 公式是例题的一部分时，不应把整道例题降维成孤立公式卡。公式可以放在 example_box 的 steps 中，或与 example_box 紧邻作为辅助公式。
- 如果 formula 字段只能写成自然语言解释，例如 “price equals ...” 或 “value equals ...”，说明该内容没有被正确建模；应改为数学表达式，并把解释移动到 usage / description / takeaway。

## 4. Office 数学对象检查规则

不能只依赖普通文本抽取结果。

如果普通文本中公式、权重、结果缺失，但 PPT 页面明显是计算题或推导题，必须进一步检查：

- Office 数学对象；
- 表格对象；
- PPT 中的公式对象；
- 页面渲染截图；
- 相邻页内容；
- chunks / slide inventory 中的信息。

如果数学对象中能确认公式、权重、结果，应写入 example_box。

如果仍无法确认：

- 保留题目结构；
- 保留解题路径；
- 保留能确认的方程或计算逻辑；
- 对无法确认的具体数字标注“需人工核对”；
- 不伪造数字。

第 4 章“用 A、B、C 附息债券复制 1 年期零息债券”的经验必须作为反例记住：普通文本抽取漏掉了 Office 数学对象中的权重和公允价值，不能因此把完整应用题降级为普通表格。

## 5. LaTeX / 数学对象写入 JSON 规则

所有写入 framework JSON 的数学变量、公式和计算式，都必须能被 MathText / KaTeX 正确识别。

必须遵守：

- 普通文本中的数学变量必须使用 MathText 可识别格式，例如 `\(N_A\)`、`\(F_0\)`、`\(S_T\)`。
- JSON 字符串中的反斜杠必须正确转义。文件中应能看到 `\\(N_A\\)`、`\\times`、`\\approx` 这类写法。
- 禁止出现 `imes`、裸 `approx`、`(N_A)`、`(3N_A+5N_B+10N_C=100)` 这类损坏公式或伪公式。
- 如果公式来自 Office 数学对象，必须转换成合法 LaTeX 后再写入 JSON。
- 数学公式应尽量放在 `formula` / `formulaLatex` 字段，或放在 MathText 可识别的文本中。
- 不要把公式混入普通中文括号里；需要行内公式时使用 `\( ... \)`。
- `\times`、`\approx`、`\leq`、`\geq`、`\max`、`\min` 等命令必须保留反斜杠。
- 写入后必须搜索检查 `imes`、`approx`、`(N_`、`N_A)`、`N_B)`、`N_C)` 等常见损坏痕迹。

示例：

- 错误：`(N_A)`
- 正确：`\(N_A\)`
- 错误：`P=-57.75 imes98.68+56.65 imes104.34-1 imes113.89approx98.2`
- 正确：`\(P=-57.75\times 98.68+56.65\times 104.34-1\times 113.89\approx 98.2\)`

## 6. 数值不确定时的处理规则

错误做法：

- 因为权重或最终数值不确定，就删除例题结构；
- 只保留表格说明；
- 把高价值例题降为 P2/P3；
- 编造 PPT 中没有的数字。

正确做法：

- 保留题目条件；
- 保留问题或判断任务；
- 保留解题思路；
- 保留方程或计算路径；
- 能确认的数字写出；
- 不能确认的数字标注“需人工核对”；
- 不伪造；
- 不把例题降级为 P2/P3。

数值不确定只影响“具体结果是否写入”，不影响“例题结构是否保留”。

### 6.1 人工复核标注的写法规则

当正文或 audit 中出现“需人工核对”时，禁止只写一句模糊提示。必须同时给出以下三项信息：

1. **具体问题描述**：哪里出现了什么矛盾、缺失或不确定。例如“同一页均值文字处为 107.90，但计算式为 107.09，两者不一致”而非“均值数字需复核”。
2. **课件精确定位**：PPT 页码、区域（文字说明 / 计算式 / 表格 / 公式对象 / 图片对象）。例如“第 59 页文字说明 vs 第 60 页计算式”而非“课件中存在不一致”。
3. **正文当前处理方式**：正文选用了哪个值、按什么逻辑处理、对学生的提示是什么。

反面示例（禁止）：

- “均值数字需人工复核。”
- “具体系数以课件公式和教师口径为准。”
- “部分数值存在不一致。”

正面示例：

> 课件第 59 页文字说明处出现均值 107.90，第 60 页计算式使用 107.09（代入 107.09−83.64=23.45），两处数字不一致。正文跟随计算式使用 107.09，data_table note 和 example_box pitfall 中已标注差异。请确认第 59 页文字是否为笔误，应以哪个数字为准。

规则要点：

- **不能把模糊标注当作“已处理”**——如果 audit 中只有“需人工核对”但没有描述具体问题和课件位置，视为未完成标注。
- **正文中的标注要让学生看得懂**——学生看到“以教师口径为准”时，应能理解这里存在一个需要老师确认的具体问题，而不是觉得正文写错了。
- **audit 中的标注要对准校对者**——校对者打开 audit 就能直接定位到 PPT 页码和矛盾点，不需要再从头翻课件。

## 7. 表格与 example_box 的关系

如果表格只是分类或对比，可以使用：

- data_table；
- comparison_table。

如果表格属于以下类型，并且后续有问题、解答或推导，则必须配套 example_box：

- 题目条件表；
- 现金流矩阵；
- 计算数据表；
- 套利收益表；
- 收益率表；
- 贴现表；
- 价格比较表；
- 公允价值计算表。

推荐组合：

- data_table 承载已知条件和数值矩阵；
- formula_card 承载核心公式；
- example_box 承载问题、步骤、计算结果和复习启示。

不要把所有表格都强行改成 example_box。单纯分类表、背景表、链接表、市场材料表，不需要生成例题卡。

### 7.1 例题输入数据表与概念分类表的视觉边界

概念分类或对比表格（如“ABS 三种情形对照”“名义利差 vs Z-spread vs OAS 对比”）用 data_table 或 comparison_table 即可充分表达。

但是以下类型的例题输入数据表具有特殊的视觉价值，不应因为“已被 example_box 或 data_table 覆盖”就直接排除 image 候选资格：

- 多路径 × 多期矩阵表（如利率路径矩阵、再融资率路径矩阵、每期现金流矩阵）；
- 多情景条件表（如多个情景的不同参数组合）；
- 大型数值矩阵（如 10+ 行的计算数据表）。

这些表格的规模感、多行并行阅读体验和结构密度是 data_table 文本渲染无法等价表达的，而这些本身就是教学内容的一部分——学生需要“看到”一张完整矩阵表才能理解 Monte Carlo 模拟的输入规模和路径多样性。

处理顺序：

1. 先判断该表是否为例题输入数据表，即它的角色是服务于 example_box 的给定条件；
2. 如果是，独立评估图片是否提供 data_table 渲染无法等价传达的直观信息，**不受“该内容已被 example_box / data_table 结构化覆盖”的约束**；
3. 不需要提取全部同类表格——通常 1-2 张代表性图片即可支撑整个例题链的直观理解；
4. 图片提取后在 chapter visual-critical-audit 中记录：为何这张表 data_table 不足以替代，图片具体提供了哪种不可替代的教学直观。

判断边界说明：

- 例题输入数据表 ≠ 概念分类表。前者是例题题干的一部分，后者是用于对比知识点的辅助表。**不应使用同一视觉处理标准。**
- 第 6 章机制图原则（Section 11）适用于“空间关系 / 曲线加点 / 校准前后对比”，它和本规则的交叉地带是：当一个表格同时也是机制图（例如“加了同一利差后所有路径现金流同步变化的矩阵表”），两个原则可以同时适用。
- 如果表格规模很小（如 2-3 行 × 2-3 列），data_table 通常就可以替代。

## 8. 图表型 visualBlock 生成规则

生成 line_chart、curve_chart、payoff_chart 前必须确认有可绘制数据点。

必须遵守：

- 不允许生成没有数据点的 line_chart / curve_chart / payoff_chart；
- 没有真实数据点时，可以使用概念点，但必须明确说明“概念示意，不是历史时间序列”或同等含义；
- 概念点只能表达方向、相对高低、曲线形状或盈亏结构，不能伪装成真实市场数据；
- 如果无法可靠给出真实点或概念点，应使用 chart_explanation；
- 如果前端图表类型要求数值型 x 轴，不要使用无法解析的文字 x 值；应改用数值阶段，并在 description 或 keyTakeaways 中解释阶段含义。
- 禁止生成只有坐标轴、标题、说明和关键结论，但没有曲线或数据线的空白图。
- 每章增强后必须检查所有图表型 visualBlocks 是否能实际渲染，包括 line_chart、curve_chart、payoff_chart。
- 检查时必须确认 `points` / `series` / `curves` 字段符合 VisualBlockRenderer 期望结构。

空白图表属于内容生成错误。图表只显示坐标轴、边框和结论，但没有曲线时，必须回到 JSON 检查 points / series / curves 是否符合渲染器期望结构。

### 8.1 chart_explanation 必须有对应图表

chart_explanation 的作用是解读一张实际存在于页面上的图表。当对应图表不存在时，chart_explanation 即退化为无意义 placeholder。

禁止以下做法：

- **禁止 chartType 为 "other" 且无对应图表**——chartType 必须指向页面上实际存在的 curve_chart、line_chart、payoff_chart、image 或其他可渲染图表。
- **禁止用 chart_explanation 替代图表本身**——不能因为 PPT 中的图表数据无法确认或无法结构化，就用一段文字摘要替代图表，然后标为 chart_explanation。如果没有对应图表可接，chart_explanation 不应存在。
- **禁止在 chart_explanation 的 keyTakeaways 中写笼统结论**——如"市场规模大、品种多、风险可发生"这类无具体数据支撑的概括，不能替代实际的图表和数据。

正确做法：

1. 如果 PPT 中有可裁切图表 → 裁切为 `image` visualBlock，再用 chart_explanation 绑定解读。
2. 如果 PPT 中有可结构化的数据 → 转换为 `data_table` 或 `comparison_table`，不需要 chart_explanation。
3. 如果数据来自 PPT 图表图片且无法裁切 → 只保留 `image`（裁切版），解读文字放入 image 的 `description` 字段。
4. 如果既无可用 image 也无结构化数据 → 不在正文中放置 chart_explanation；可在 audit 中记录 PPT 有图表但当前无法接入。

反面案例（来自第 1 章，已修复）：

> VB type: chart_explanation, chartType: "other"。内容只有三条 keyTakeaways 文字（"规模大、品种多、风险可发生"），没有 image、curve_chart、data_table 或任何对应图表。PPT slides 12/22 中真实的市场规模图、违约数据图未被裁切，而是被一段笼统文字替代。

这个反例的根因是：生成时看到 PPT 中有图表内容，但图表数据嵌入在图片中无法文本抽取，于是写了文字摘要并标为 chart_explanation 应付过去。正确做法应该是裁切 PPT 中的原始图表为 image，或从 PPT 文本层中提取可用数据转为 data_table。

每章增强后的 chart_explanation 检查：

- chart_explanation 所指向的图表是否存在于同一章节的 visualBlocks 中？
- 如找不到对应图表，必须替换为 image + description、data_table，或删除并在 audit 中记录。

## 9. 强视觉对象审计与接入规则

每章内容生成必须先审计“强视觉对象”。如果 PPT 中某个内容本质上依赖空间结构、节点关系、路径关系、时间状态关系、图形走势、现金流方向或 payoff 形状，且文字、公式或表格不能等价表达，就不能只写成普通说明。

强视觉对象包括但不限于：

- 利率树、二叉树、三叉树、含权债估值树、现金流树、回溯估值树；
- payoff 图、债券价格-收益率关系图、久期/凸性图、收益率曲线、利率期限结构图；
- 现金流时间轴、现金流方向图、套利复制结构图、期权行权判断节点图；
- 真正依赖节点判断的决策树，以及风险分解图。

视觉对象必须按 A/B/C 分级：

- A 类：必须可视化。没有图示会显著影响理解，不能只用文字、公式、data_table 或 example_box 替代，必须进入网页正文。若现有 visualBlock 无法表达，应优先尝试局部图片裁切；如果裁切失败，必须记录具体技术阻塞和临时替代方案。
- B 类：建议可视化。有图更清楚，但文字、表格、chart_explanation 或结构化 visualBlock 可以基本表达。可视质量足够时可以裁切图片。
- C 类：不应可视化。新闻链接、机构页面、市场截图、数据库页面、低价值外部阅读等，如果不直接服务 P0/P1，不进入网页正文，只在 audit 中记录。

利率树特别规则：

- 入门利率树图、利率树校准结果图、含权债券估值树默认属于 A 类或强 B 类；
- 出现 `Interest rate tree`、利率树形图、二叉树利率模型、节点、上行/下行、高/低利率、回溯估值、校准利率树、可赎回/可回售债券估值树时，必须判断是否需要图示；
- 利率树不得只处理成文字说明、data_table 或 example_box；
- 如果没有原生 `interest_rate_tree` / `lattice_tree` visualBlock，必须优先尝试局部图片裁切或基于 PPT 确认数据进行结构化重绘，并在 audit 中说明来源、坐标或重绘依据、版权风险和是否需要前端能力补充。

每章增强或复审后必须生成或更新视觉审计文件，例如：

`data/generated/<courseId>/audit/chXX-visual-critical-audit.md`

审计表至少包含：

| PPT 页 | 视觉对象 | 类型 | 分级 A/B/C | 当前网页表达 | 是否需要图片/visualBlock | 处理结果 | 理由 |
|---|---|---|---|---|---|---|---|

如果 A 类强视觉对象未进入网页正文，不能直接汇报完成；必须说明为什么不能接入、是否是前端不支持、是否缺少稳定图片路径、是否导出或裁切失败、临时替代方案是什么，以及是否需要新增原生 visualBlock。

强视觉对象还必须通过“位置正确性”检查：

- A 类强视觉对象不得只进入资源索引、补充材料、章节底部或与知识点脱节的位置。
- A 类强视觉对象必须进入它解释的知识点模块；如果无法匹配，说明模块标题、节点摘要或 visualBlock 标题需要调整。
- 如果某个知识点依赖图示才能理解，图示应位于首次抽象解释之前，或紧随模块导读之后。
- 图表说明必须紧贴对应图片、曲线、现金流图、树图或 payoff 图，不得与图片分离到模块底部。
- 对空间结构型对象，例如利率树、现金流图、决策树、收益率曲线、payoff 图、流程图，必须优先考虑“先图后解释”的教学顺序。
- “A 类对象进入正文”不等于合格；还必须检查是否进入正确模块、是否早于依赖它的抽象说明、是否与读图说明相邻。

## 10. 教学依赖顺序与内容编排规则

内容生成不能只按 visualBlock 类型机械堆叠，也不能把“公式区 / 图片区 / 例题区”分开堆放。每个学习模块内部必须按学习依赖关系排序。

推荐顺序：

1. 模块导读；
2. 必要前置图示、结构图、树图、曲线图、现金流图或 payoff 图；
3. 图示阅读说明；
4. 核心概念、节点符号或变量定义；
5. 基本关系式或公式；
6. 例题、案例、校准过程或计算过程；
7. 流程总结；
8. 易混点、复习要点；
9. 资源索引、补充材料或拓展材料。

这不是死板模板。Codex 可以根据课程内容调整顺序，但必须能说明教学理由。特别是：

- 如果图示是理解基础对象的入口，应先图后解释。
- 如果流程图总结的是一套方法或操作过程，应放在学生已经理解基础对象、核心变量、关键图示和至少一个代表性例题之后。
- 如果流程图本身是“研究流程概览”或章节导航，可以放在模块前部；必须区分“前置认知图”和“后置总结图”。
- 多个 visualBlocks 属于同一知识链条时，应形成“图示 → 解释 → 公式 → 例题 → 复习要点”的路径，而不是散落在不同模块或底部区域。

图示与例题必须尽量绑定：

- 利率树图应绑定节点符号、路径说明和建树例题。
- 现金流图应绑定现金流折现例题。
- payoff 图应绑定对应期权或策略收益解释。
- 决策树应绑定递推估值或决策步骤。
- 收益率曲线应绑定期限结构解释和曲线变化含义。
- 数据表应绑定对应计算、比较或判断逻辑，而不是孤立放在章节底部。
- 流程图应绑定它总结的流程，不应早于流程中的基础概念和前置例题。

资源索引和补充材料的边界：

- 资源索引只做定位和跳转，不应重复完整正文。
- 补充材料只放无法可靠匹配到学习模块、且不属于主线理解所必需的内容。
- A 类强视觉对象、核心公式、核心例题、支撑核心知识点理解的图表说明、与 P0/P1 内容强绑定的案例或计算过程，不应被放入补充材料。
- 如果某内容是理解主线所必需，应进入对应学习模块，而不是进入补充材料。

## 11. PPT 局部图片裁切与 image visualBlock 规则

PPT 局部图片只能在确实能提升复习理解时使用。图片不是“完整吸收 PPT”的证明，也不能替代已经能结构化表达的公式、例题、表格和流程。

允许使用 PPT 局部图片的情况：

- 图片直接服务 P0/P1 核心考点；
- 图片能明显帮助理解核心机制；
- 图片比文字、表格、chart_explanation 或可绘制图表更适合表达该内容；
- 图片展示的是难以结构化复现的关键图示、机构界面局部、市场实践局部或特殊表格；
- 图片属于强 P2 补充材料，并且不会干扰主学习路径。

机制图补充原则：当 PPT 图片直接表达抽象公式背后的空间关系、曲线加点关系、模型校准前后变化、节点加点逻辑或价格匹配过程时，即使该内容也能用 `formula_card` / `example_box` 表达，仍应优先评估为可用图片候选；若图片清晰、非整页、直接服务 P0/P1，并且能放在对应知识点附近，就应作为 `image` visualBlock 接入，而不是仅在 audit 中记录。

典型可用情形：

- Z 利差类图片：展示“基准即期曲线 + 固定利差”的整体关系，而不是只重复公式；
- OAS 类图片：展示“利率树节点加 OAS → 模型价格匹配市场价格”的校准机制；
- 例题 / 校准截图：展示计算路径、模型价格调整前后对比、Excel 单变量求解或节点加点动作，但不能替代 `example_box`。

不可用边界：标题、外部链接、新闻截图、数据库页面、长篇政策材料不因出现在 PPT 中而进入正文。

不应使用图片的情况：

- 纯新闻链接、研究报告链接、数据库链接；
- 机构页面整页截图；
- 只用于“了解市场实践”的截图；
- 无法读清、无法解释、无法验证的截图；
- 与 P0/P1 或强 P2 没有直接关系的截图；
- 只是为了证明 PPT 中出现过的图片。

裁切必须遵守：

- 禁止截整页 PPT 作为网页图片；
- 只裁切真正有教学价值的局部区域，优先裁切图表、表格、机构页面中的关键区域；
- 图片必须清晰，不能明显模糊；
- 图片不能包含大量无关页眉、页脚、空白或课件装饰；
- 不要裁切与学习目标无关的背景图；
- 不要使用本地绝对路径；
- 不要引用不存在的图片；
- 如果无法稳定提取图片，不要退而求其次保留空泛文字，应只在 audit 中记录。

图片路径约定：

- 图片保存到 `public/generated-assets/<courseId>/chXX/<name>.png`；
- 文件名使用英文小写和短横线，不使用中文、空格或临时命名；
- `image` visualBlock 的 `src` 使用站点可访问路径，例如 `/generated-assets/gdsyzq/ch04/example-name.png`；
- 写入 JSON 前必须确认文件真实存在。

image visualBlock 必须包含：

- 具体的 `title`，不能写“重要截图”“拓展图片”；
- 清楚的 `alt`，描述图片实际内容；
- 说明教学用途的 `description`；
- 如需补充使用边界，可写 `caption`。

禁止写入空泛说明，例如：

- “该截图用于了解机构实践。”
- “因数据未可靠结构化，不作为主视觉图表。”
- “该图片仅作拓展阅读。”

每次接入图片必须在 audit 中记录：

- source PPT 文件名；
- slide 页码；
- 裁切坐标和坐标单位；
- 输出图片路径；
- 所在模块和 image visualBlock 标题；
- 教学价值与复习优先级；
- 是否替代或删除了原来的空泛拓展材料；
- 版权风险和是否适合公开部署；
- 是否建议后续批量采用。

图片数量必须克制。单章图片不是越多越好；如果没有合适图片，可以 0 张。一般应控制在 1-5 张内，超过 5 张必须说明每张为什么必要。不得为了完整吸收 PPT 而强行保留低价值截图说明。

## 12. 每章增强前必须产出

每章增强前必须产出或更新：

- slide inventory：逐页清点 PPT/PDF 内容；
- priority map：按 P0/P1/P2/P3 做复习价值分层；
- example / application / derivation audit：审计例题、应用题、连续页推导链；
- enhancement plan：说明计划新增或重排的模块、知识点、公式、例题和 visualBlocks；
- visual critical audit：审计强视觉对象，特别是树形图、曲线图、现金流图、payoff 图和节点回溯图。

这些文件不是形式化清单，而是防止生成阶段过度概括、误删例题、误把拓展材料放入主路径的工作依据。

## 13. 每章增强后必须产出

每章增强后必须产出或更新：

- priority review：记录最终哪些内容进入主路径，哪些被降权或移入拓展；
- 增强前后统计：nodes、formulas、examples、cases、visualBlocks 及类型分布；
- validate / lint / build 结果；
- 预览路径；
- 无法确认的数据、图片、公式或案例细节；
- 所有图表型 visualBlocks 的可渲染检查结果；
- A 类强视觉对象是否已进入网页正文；若未进入，必须记录阻塞原因和下一步动作。

每章增强后还必须执行教学编排审计：

1. 是否存在 A 类强视觉对象只出现在补充材料、资源索引或章节底部。
2. 是否存在图示说明和图片分离。
3. 是否存在先讲抽象符号 / 公式，后放关键图的情况。
4. 是否存在本应为例题的内容被输出为孤立 formula_card。
5. 是否存在流程图被过早放在学生尚未理解基础对象之前。
6. 是否存在 formula_card 缺少已知条件、问题目标、求解过程，却实际承担例题功能。
7. 是否存在多个 visualBlocks 属于同一知识链条但被拆散到不同位置。
8. 是否存在资源索引重复正文内容，或补充材料吞掉主线内容。
9. 是否存在图示、公式、例题分别存在，但没有形成“图示 → 解释 → 公式 → 例题 → 复习要点”的学习链条。
10. 是否存在 formula 字段中放入自然语言解释，而不是数学表达式。
11. 是否存在半 LaTeX 文本，例如 `(i_{1,H})`、`(sigma=15%)`、`(e^{2sigma})` 未规范写为 `\( ... \)`。

如果发现原计划中有误判，必须同步修正 audit 文件，不能让旧的错误判断留在文档里。

## 14. 禁止事项

生成和增强时禁止：

- 把所有 PPT 内容等权展示；
- 把新闻链接、截图、市场背景放到核心路径前面；
- 为了完整硬塞 visualBlocks；
- 因为公式对象抽取不完整就删除例题；
- 因为数值暂时不确定就删除题目结构；
- 伪造 PPT 中不存在的数据、权重、案例或结论；
- 把完整应用题降级成普通表格；
- 把连续页推导拆散成零散说明；
- 把核心例题降为 P2/P3；
- 用公式卡或数据表替代完整 example_box；
- 把实际承担例题功能的公式卡孤立展示；
- 把 A 类强视觉对象放到模块底部、补充材料或资源索引里；
- 让图示说明与对应图片、曲线、现金流图、树图或 payoff 图分离；
- 在学生尚未理解基础对象前放置后置总结型流程图；
- 写入 `imes`、裸 `approx`、`(N_A)` 这类损坏公式或伪公式；
- 生成没有数据点或数据结构不匹配的空白曲线图；
- 修改 schema 或页面代码来掩盖内容生成不足。

最终目标是让课程页面成为“期末复习路径”：

- 学生能清楚看到哪些必须掌握；
- 哪些重点理解；
- 哪些只是辅助；
- 哪些属于拓展；
- 每个核心例题都能看到条件、问题、解法、结果和复习启示。


## 附录：金融计量学 / Stata 复现型课程内容生成规范（jrjlx 第一讲经验沉淀）

本节沉淀自 jrjlx 第一讲“面板数据”的多轮内容生成、页面复审和零基础学习体验优化。后续生成金融计量学，以及任何包含软件实操、数据文件、日志输出和回归表复现的课程时，必须优先套用本节规则。

### 适用课程类型

当课程材料同时包含课件/PDF、数据集、程序脚本、运行日志和目标表格时，不得按普通“课件摘要增强”处理，而应按“模型概念 + 软件操作 + 输出阅读 + 表格复现 + 考试表达”的复现型课程处理。

典型材料包括：

- 讲义/PDF：负责解释概念、模型动机、公式和课堂逻辑。
- 数据集（如 .dta）：负责承载实证任务，必须说明变量、个体维度、时间维度和使用场景。
- do 文件：负责说明学生实际要运行的命令，不得编造未在材料中出现的命令。
- log 文件：负责提供可追溯的真实输出，所有确定数值都必须来自 log、表格图片或真实运行结果。
- 回归表图片/教材表：负责定义复现目标，不应只当作装饰图片。

### 生成总链路

复现型课程必须建立以下链路：

讲义主题 → 数据文件 → do 文件命令 → log 输出 → 回归表单元格 → 经济含义 → 考试/作业表达。

如果链路中任何一环无法追溯，应明确标注“需要补充核查”，不要为了页面完整而补数值、补命令或补结论。

### 零基础教学顺序

章节结构应像一本可自学教材，而不是材料陈列。推荐顺序如下：

1. 先用直白语言说明这一讲到底学什么，学完能做什么。
2. 解释本章会用到哪些文件，每个文件是什么、干什么、在哪一步出现。
3. 解释软件界面和操作入口：命令输在哪里、输出看哪里、do 文件在哪里运行、数据在哪里查看。
4. 补齐第一次开工步骤：解压材料、打开软件、设置工作目录、确认目录、加载数据。
5. 再进入数据结构：变量、观测值、样本量、个体维度、时间维度、balanced/unbalanced panel。
6. 每个模型按“为什么需要 → 公式/直觉 → 命令 → 输出怎么看 → 表格怎么填 → 考试怎么写”的闭环展开。
7. 最后给综合检查清单和考试表达模板。

不要在首屏堆入过多术语。首屏的任务是建立学习路径，不是把所有概念一次性讲完。

### 命名与模块组织

- 模块标题不要写“模块 00”“模块 01”。前端会自动编号，内容标题应像教材小节，例如“这一讲到底学什么”“从 fatality.dta 到 TABLE 10.1”。
- 导读模块不要塞入中后段模型总结，避免学生还没学操作就先被 OLS、FE、cluster、RE 等术语轰炸。
- 术语解释应跟随第一次使用场景出现。比如 N/T/groups/observations 应放在 xtset 或面板输出附近；内生性、遗漏变量偏误应放在 OLS 不够之后；IV 直觉应放在 HT 之前。
- 长章节允许更长、更细，但必须有清晰主线。金融计量课程优先保证可自学，不优先追求简洁。

### 术语释义要求

第一次出现的关键名词必须给白话解释、课程例子和学生要会说的话。不要只给术语翻译。至少覆盖：

- 数据基础：变量、观测值、样本量、被解释变量、解释变量、控制变量。
- 面板基础：横截面、时间序列、面板数据、个体维度、时间维度、N、T、groups、observations、balanced panel、unbalanced panel。
- 回归基础：OLS、pooled OLS、系数、截距项 _cons、残差/误差项、R-sq、within/between/overall R-sq。
- 推断基础：Std. Err.、robust standard error、clustered standard error、t 值、z 值、P>|t|、P>|z|、F 检验、Wald 检验、H0、拒绝/不拒绝 H0。
- Stata 语法：do 文件、log 文件、Results、Command、use ..., clear、cd、pwd、dir、xtset、i. 前缀、dummy variable、vce(cluster ...)、test、testparm、estimates store。
- 模型风险：外生性、内生性、遗漏变量偏误、共线性、omitted because of collinearity。
- 面板模型：FE、within 变换、LSDV、FD、Between、RE、Hausman 检验、Hausman-Taylor、IV 的最低限度直觉。

不要连续堆 5 张以上密集术语表。优先使用“叙述 + 小例子 + 小表格”的组合；表格用于对照，不应替代讲解。

### Stata 实操最低标准

任何 Stata 复现型章节都必须让学生知道第一步怎么开始。至少写清：

- 如何准备材料：解压课程材料，记住工作目录。
- 如何打开 Stata，以及主界面的 Command、Results、Review、Variables、Properties、Do-file Editor、Data Editor 各自做什么。
- 如何设置和核对工作目录：cd、pwd、dir。
- 如何加载数据：use 数据名, clear，并解释 clear 是清空内存中旧数据，不是删除文件。
- 如何查看数据结构：describe、Variables 窗口、Data Editor。
- 如何声明面板：xtset 个体变量 时间变量，并解释它只是告诉 Stata 哪列是个体、哪列是时间，不是文件名，也不是把数据转换成另一种文件。
- 如何打开 do 文件、选中关键行、分段运行、查看 Results。
- 如何生成、打开或核对 log 文件。
- 常见报错如何处理：file not found、variable not found、panel variable not set、repeated time values within panel、not sorted、omitted variables、Hausman warning。

Hausman 命令链必须完整。若使用 hausman fe_est re_est，前面必须出现并解释：

```stata
xtreg ..., fe
estimates store fe_est
xtreg ..., re
estimates store re_est
hausman fe_est re_est
```

其中 estimates store 要解释为“暂存刚才的回归结果，方便之后比较”，不是新的回归模型。

### 输出块与数值真实性

核心 stata_output_block 必须添加 annotations，不能只贴原始输出。按实际输出中出现的字段解释：

- Coef.：系数，回答方向和大小。
- Std. Err.：标准误，影响 t/z 值和显著性。
- t、z：系数除以标准误后的统计量。
- P>|t|、P>|z|：p 值，判断统计显著性。
- Number of obs：实际进入回归的观测数。
- groups：面板中的个体数。
- R-sq / within R-sq / between R-sq / overall R-sq：解释度，FE 中尤其要提醒学生为什么常看 within。
- sigma_u、sigma_e、rho：面板误差结构字段，至少给白话解释。
- corr(u_i, Xb)：个体效应与解释变量拟合部分的相关性，出现时必须解释，不可放任学生猜。
- warnings / notes：例如 omitted、not positive definite、not sorted 等，要说明原因和处理方式。

禁止编造 Stata 输出、回归数值、显著性星号或样本量。所有确定数值必须能追溯到 log、表格图片、真实 Stata 运行结果或已核查的数据文件。

### 回归表复现要求

regression_table 和 table_mapping_block 不只是展示结果，必须教学生如何复现。每个可追溯列尽量包含：

- tableColumn：教材表第几列。
- model：该列估计的模型。
- command：对应 Stata 命令。
- logSource：对应 log 文件和输出位置。
- coefficientPath：系数从输出哪一行哪一列来。
- stdErrPath：标准误从哪里来。
- pValuePath：p 值或显著性从哪里判断。
- examInterpretation：考试/作业中如何解释。
- caution：相对上一列新增了什么、哪些地方不要误读。

至少给一个“从 log 到表格单元格”的完整示范：先指出命令，再截取或展示 log 片段，圈出/标注 Coef.、Std. Err.、p 值，最后说明它填入教材表的哪一列哪一行。

如果同一部分包含教材表内复现和表后扩展检验，应分层说明。例如 TABLE 10.2 应区分 BE/FE/OLS clustered/RE 等表内列，与 Hausman、Hausman-Taylor 等表后模型选择或扩展。不要把“表里有的列”和“表后为了理解模型追加的检验”混成一张无法辨认的表。

### 图片资源规则

复现型课程的图片必须承担教学职责，不做装饰。优先使用真实软件截图，并允许做裁切、打码、箭头、框选和文字标注。若无法可靠获取真实软件截图，可以生成高保真教学示意图，但必须标明其教学示意性质，不得伪装成真实回归结果截图。

建议图片类型：

- Stata 主界面总览：Command、Results、Review、Variables、Properties。
- Do-file Editor 与 Results 对照：选中命令、运行按钮、输出位置。
- Data Editor / Variables 识别：个体变量、时间变量、核心回归变量。
- 文件关系图：讲义、dta、do、log、表格之间的关系。
- 面板结构图：个体维度 × 时间维度。
- xtset 概念图：给数据贴上“个体”和“时间”两个标签。
- within 变换直觉图：同一个体和自己的平均值比较。
- 表格映射图：命令 → log 输出 → 回归表列 → 考试解释。

所有公开引用图片不得暴露本机用户名、绝对路径、授权信息或与课程无关的私人界面。

### 考试表达与练习边界

除非用户明确要求，或课件/教材中已有例题，不要凭空新增练习题。金融计量课程可以增加“考试表达”“答题路径”“解释清单”“易错点”，但不要虚构新的题目、数据或答案。

推荐在每个核心概念后放一句可直接复用的考试表达，例如：

- FE：本模型通过个体固定效应控制不随时间变化的个体差异，系数主要由同一个体内部随时间变化来识别。
- cluster：聚类标准误修正同一组内误差相关导致的标准误偏小问题，它不改变系数估计本身。
- Hausman：若 p 值较小，通常拒绝“个体效应与解释变量不相关”的原假设，倾向采用 FE。

最后再汇总模板即可，不要把所有考试帮助都堆到最后。

### 审计报告与验收检查

每轮生成或重构后，审计报告至少记录：

- 使用了哪些源文件，每类文件承担什么内容。
- 生成了哪些模块和 visualBlocks。
- 哪些结果来自 log，哪些来自讲义，哪些来自表格图片，哪些来自真实软件截图。
- do/log/table 的对齐情况。
- 哪些数值、列映射或命令仍需人工核查。
- 图片资源来源、用途和是否脱敏。
- 是否删除或替换了占位图片路径。
- 是否存在无法追溯的结论。

验收时至少检查：

- JSON 可以解析。
- 无错误课程 ID 或历史临时拼写。
- 无草稿图片占位符。
- 无本机绝对路径或用户名泄露。
- 无未定义值、非数字值、中文乱码或替换字符。
- formulaLatex 不含自然语言、$$、\[、\]。
- Stata 数值均可追溯。
- 不生成或维护不再使用的 concise 版本。
- 必要时运行内容校验、lint 和 build；若只是底层文档更新，可说明未运行构建的原因。

### 产品复审机制

复现型课程生成后，必须从“完全没学过的学生”和“产品用户”两个视角复审，而不是只做内容正确性检查。复审重点包括：

- 学生打开页面是否知道从哪里开始。
- 是否知道如何准备材料、打开软件、设置目录、运行 do 文件。
- 是否知道每个新文件、新命令、新字段是什么。
- 模块之间是否有突然跳转。
- 是否存在术语墙、表格墙或长输出墙。
- 回归表是否能从命令和 log 一格一格复现。
- 考试表达是否分散在概念附近，而不是全部堆到最后。
- 桌面端和移动端是否都能阅读长表、代码块和输出块。

目标不是让页面显得专业，而是让零基础学生能够独立完成“理解概念 → 操作 Stata → 阅读输出 → 复现表格 → 写出答案”的完整闭环。

## 附录：jrjlx ch00/ch01/ch02 结构复盘与后续生成标准

本节总结 jrjlx 第 0 讲、第 1 讲、第 2 讲落地后的结构标准、visualBlocks 使用标准、Stata 复现链路标准、去重规则和后续章节注意事项。ch01“面板数据与 Stata 复现”是修改轮次最多、产品审查最充分的章节，后续金融计量学专题章应优先以 ch01 的最终形态作为模板，而不是回到普通“课件摘要增强版”。

### 1. 三章职责分工

jrjlx 已形成“预备课 → Stata 复现主模板 → 专题模型复现”的层级。

- ch00《回归复习与 Stata 入门》负责预备能力：简单回归、OLS、EViews 输出阅读、置信区间、假设检验、p 值、Stata 文件类型、beauty.dta / beauty.do / beauty.smcl 入门。后续章节不得反复重讲这些通用基础，只能做短提醒和链接式回顾。
- ch01《面板数据与 Stata 复现》负责课程主模板：认文件、认面板数据、运行面板命令、读 log、复现 TABLE 10.1 / TABLE 10.2、解释 FE / cluster / RE / Hausman / HT、写考试表达。它是后续 Stata 复现型章节的默认结构样板。
- ch02《工具变量》负责专题扩展：在 ch00 的 OLS / 假设检验基础和 ch01 的 do/log/table 复现能力之上，学习内生性、IV、TSLS、第一阶段 F、J 检验和 Table 12.1 映射。

后续新增章节必须先判断自己属于哪一层：如果是基础概念或软件通用操作，优先归入 ch00 或做“回看 ch00”；如果是新模型专题，应沿用 ch01 的复现链路，而不是重新发明页面结构。

### 2. ch01 最终结构标准

ch01 的最终结构不是“讲义重写”，而是一条可跟练的学习路径。后续 Stata 复现型专题章应参考以下顺序：

1. 开头说明本章到底解决什么问题，学生学完能做什么。
2. 给出与前置章节的边界：通用回归 / Stata 入门见 ch00，本章只讲本专题特有内容。
3. 快速说明本章材料：PDF、dta、do、log、表格图片分别承担什么角色。
4. 先认数据和任务，再给命令。不要一上来抛命令。
5. 先讲为什么需要该模型，再讲公式和命令。
6. 对核心命令建立“命令 → log 输出 → 表格列 → 经济含义 → 考试表达”的闭环。
7. 对输出块做字段标注，告诉学生先看哪几行。
8. 对教材表至少做一列完整搬运示范。
9. 最后给考试/作业表达模板，但核心模块旁边也要放短考试表达，不要全部堆到最后。

ch01 已经证明，零基础自学页需要比普通课程页更长、更细、更像教材。长度不是问题，断裂感才是问题。页面应让学生知道“现在为什么切到这份数据、为什么运行这条命令、为什么看这个输出、为什么这个数字进表格”。

### 3. visualBlocks 使用标准

jrjlx 后续章节应优先复用已经验证过的 visualBlocks，而不是新增 schema。

- callout_teacher_note：用于老师口授式解释、误区提醒、考试提醒、章节衔接和去重提示。ch01 中最有价值的用法是解释“OLS 正、FE 负不是矛盾”“cluster 不是 FE”“Hausman 的 H0 不要写反”。
- dataset_schema：用于说明 dta / xlsx 数据结构。必须写明数据用途、核心变量、个体维度、时间维度或样本单位。不要做过长变量清单。
- stata_code_block：只放真实 do 文件中出现或与真实材料一致的命令。每个块必须写来源、用途、运行后看什么。
- stata_output_block：只放真实 log / smcl / 真实运行输出。核心输出必须加 annotations，解释 Coef.、Std. Err.、P>|t|、R-sq、Number of obs、groups、rho、Instrumented、Instruments 等实际出现字段。
- regression_table：用于结构化教材表，但不能替代复现解释。必须标明哪些列来自 log，哪些只来自表图，哪些待核查。
- table_mapping_block：复现型章节的核心块。必须串起 tableColumn、model、command、logSource、coefficientPath、stdErrPath、pValuePath、examInterpretation、caution。
- reproduction_steps：用于学生跟练路径。每步要写 command、expectedOutput、check、explanation、sourceFiles。
- comparison_table：适合做概念对照、模型对照、字段速查。不要连续堆 5 张通用术语表。
- process_flow：适合做章节路线、复现流程、检验流程。不要过早替代概念解释。
- image：用于真实软件截图、表格图、教学重绘图。教学重绘图必须在 caption 中写明“教学示意图 / 根据讲义内容重绘 / 不是原始软件截图”。
- exam_task、interpretation_checklist、common_stata_error：用于考试表达、读表清单和报错排查。不要凭空新增课件外练习题；可以写答题路径和常见误区。

图片和截图标准：真实回归结果截图不得伪造；真实软件截图应遮盖路径、授权信息和隐私内容；教学重绘图必须说明来源性质；表格图片如果无法可靠复制到 public，应改用结构化 regression_table / table_mapping_block，并在 audit 说明。

### 4. Stata 复现链路标准

所有 jrjlx 后续专题章必须建立以下链路：讲义主题 → 使用文件 → 数据结构 → do 命令 → log 输出 → 表格单元格 → 经济解释 → 考试表达。

- 讲义主题：说明本章为什么要学这个模型或检验。
- 使用文件：列出 PDF、dta/xlsx、do、log/smcl、表图，并说明每个文件“是什么、干什么、什么时候用”。
- 数据结构：用 dataset_schema 说明核心变量和样本单位。面板数据必须写 panelId / timeId；非面板数据必须写样本单位和核心变量。
- do 命令：提取真实命令，不编造。若为了教学展示简化命令，必须说明“教学版展示，保留真实命令链，清理无意义注释”。
- log 输出：只截取关键片段，不全文搬运；所有确定数值可追溯。
- 表格复现：至少做一个“从 log 到表格单元格”的完整示范。
- 经济解释：不要只写“显著/不显著”，必须解释系数方向、单位、模型设定和识别含义。
- 考试表达：给出学生可以写进作业或考试的标准句，同时标出容易扣分点。

如果 do/log/table 不完全匹配，必须显式标注。例如 ch02 Table 12.1 第 (2) 列只来自教材图片、未由本地 do/log 复现；这种情况必须写清“不可作为本页已复现结果”，不能为了页面完整而假装三列都由 log 复现。

### 5. 去重规则

ch00 建立后，后续章节必须避免重复讲通用基础。

应归 ch00 的内容：

- 变量、观测值、样本量、被解释变量、解释变量、控制变量。
- 系数、截距、残差、标准误、t 值、p 值、显著性。
- H0 / H1、拒绝 / 不拒绝、置信区间、R²、SER。
- EViews 输出阅读与 Stata 输出字段的通用对应。
- dta、do、log、smcl、工作目录、cd、pwd、dir、do 文件运行、log/smcl 查看。
- beauty.do 这类软件入门演示。

后续章节保留的方式：

- 用 1 个 callout_teacher_note 提醒“通用含义见第 0 讲”。
- 用 1 张短 comparison_table 做本章语境速查，只保留本章需要关注的差异。
- 当通用字段在本章有新含义时才展开，例如 FE 输出的 within R-sq、groups、rho，IV 输出的 Instrumented / Instruments / first-stage F / J test。
- 不要连续堆通用词典表，不要重新讲 Stata 主界面，不要重新讲如何设置工作目录，除非该章节有新的软件操作入口。

ch01 去重后的标准写法是：

- “Coef.、Std. Err.、t、P>|t| 的通用含义见第 0 讲；本讲只关注它们在面板回归和聚类标准误中的变化。”
- “如何设置工作目录、运行 do 文件、查看 log/smcl，见第 0 讲 Stata 入门模块。本讲从面板数据材料开始。”
- “OLS 基础已在第 0 讲复习；本讲重点是为什么 pooled OLS 在面板数据中可能不够。”

不要把去重做成断裂。第一讲和后续章节仍应保留本章特有的最低解释，例如 xtset、panel variable、time variable、balanced panel、groups、within R-sq、clustered standard error、Hausman H0。

### 6. ch00 / ch01 / ch02 可复用经验

ch00 经验：

- 预备课要承担“补底座”的职责，不能把所有基础都塞到正式模型章节里。
- 从 EViews 到 Stata 的过渡要明确告诉学生：软件语言变了，回归输出的统计含义没有变。
- beauty.do 展示应使用教学版代码块：保留真实命令链，清理无意义注释，路径只给示例，并明确不要照抄占位符。
- beauty.smcl 必须说明是 Stata 运行日志，不是手写答案。

ch01 经验：

- ch01 是复现型章节主模板。它必须先说明文件，再说明数据，再说明命令，再说明输出和表格，不应从模型定义直接跳到回归表。
- 面板数据教学必须特别解释 xtset：它是命令，不是文件；作用是告诉 Stata 个体维度和时间维度；不会修改原始 dta 文件。
- FE、within、LSDV 要放在同一知识链里讲，避免学生以为它们是三个互不相关的技巧。
- cluster 必须和 FE 区分：FE 解决时间不变遗漏因素，cluster 解决组内相关导致的标准误问题。
- TABLE 10.1 是 ch01 主教学表，必须重点做命令-log-表格映射；TABLE 10.2 / Hausman / HT 要分清表内复现和表后扩展。
- 审查反馈必须进入内容生成规范：术语墙、表格墙、操作断点、路径误抄风险都要在后续章节避免。

ch02 经验：

- 工具变量章节要承接 ch00 的 OLS 外生性和 ch01 的复现链路，不能把 IV 写成纯理论摘要。
- Table 12.1 这类表必须先给复现状态总览：哪些列已由 log 复现，哪些只来自教材图片，哪些待人工核查。
- 第一阶段 F、弱工具、J 检验要分别解释“看什么、为什么看、考试怎么写”。
- 如果 J 检验拒绝，只能说明至少有工具可能有问题，不能定位哪个工具坏。
- 对截距、表源版本差异、do/log 缺列等问题，不要强行修正或编造原因，应保留风险说明。

ch03 经验：

- 如果某章只有讲义 PDF、没有 do/log/dta/xlsx 等配套材料，应先判断是否属于“识别设计型 / 概念案例型章节”，不得为了延续 ch01/ch02 的形式而伪造 Stata 复现链路。
- 实验、自然实验、RD、DID 这类章节的主线应是“研究问题 -> treatment/control/outcome -> 外生变化来源 -> 关键假设 -> 威胁与稳健性 -> 考试表达”，而不是“命令 -> 输出 -> 表格”。
- 对 DID 必须讲清单纯处理后横截面对比和单纯处理组前后对比各自的问题，再进入双重差分；平行趋势要明确为“未处理时趋势相同”，不是“处理前水平相同”。
- 对 RD 必须区分锐利 RD 与模糊 RD。模糊 RD 可以和 IV 思想衔接，但不要重讲 ch02 的完整 TSLS 复现流程。
- 教学重绘图要标注“教学示意图 / 根据讲义内容重绘”，尤其是潜在结果、随机分配、RD 阈值、DID 2x2 和平行趋势图；不要把重绘图说成原始数据或原始软件截图。

### 7. 后续章节生成流程

后续生成 jrjlx 新章节时，按以下流程执行：

1. 先只读核查已有 ch00/ch01/ch02，确认新章是否重复已有基础。
2. 清点新章资料：PDF 页码主题、dta/xlsx 数据、do 命令、log/smcl 输出、表格图片、其他资源。
3. 判断本章定位：预备基础、面板/时间序列/IV/其他专题、软件实操、表格复现、考试复习。
4. 先写资料关系和复现目标，不急着生成 JSON。
5. 生成模块时沿用 ch01 闭环：概念直觉 → 数据 → 命令 → 输出 → 表格 → 解释 → 考试表达。
6. 对所有确定数值做追溯标记；无法追溯则写待核查。
7. 检查是否重复 ch00；重复内容压成短提醒。
8. 检查是否需要真实截图或教学重绘图；教学重绘图必须标注来源性质。
9. 更新 audit report，记录源文件、do/log/table 映射、图片来源、待核查项和验证结果。
10. 运行内容校验、lint、build；若只改底层文档，可说明未运行构建的原因。
